```text
│   │   ├─ 多因素认证 (MFA): TOTP/HOTP/WebAuthn/FIDO2
│   │   ├─ SSO: SAML / OAuth 2.0 / OIDC
│   │   └─ 无密码: Passkeys (WebAuthn/生物识别)
│   │
│   ├─► 授权 (Authorization)
│   │   ├─ RBAC: 基于角色的访问控制
│   │   ├─ ABAC: 基于属性的访问控制
│   │   ├─ ReBAC: 基于关系的访问控制 (Google Zanzibar)
│   │   └─ Policy-as-Code: OPA / Cedar
│   │
│   └─► JWT (JSON Web Token)
│       ├─ 结构: Header.Payload.Signature
│       ├─ 安全: HS256 (对称) / RS256/ES256 (非对称)
│       └─ 风险: 泄露即授权、无法撤销、Payload过大
│
├─► 传输安全
│   ├─► TLS 1.3
│   │   ├─ 握手: 1-RTT (首次) / 0-RTT (恢复)
│   │   ├─ 完美前向保密 (PFS): ECDHE
│   │   └─ 证书: X.509、Let's Encrypt、证书透明度
│   │
│   └─► mTLS (双向 TLS)
│       ├─ 服务间认证: 证书即身份
│       └─ 适用: 服务网格、微服务内网通信
│
├─► 应用安全
│   ├─► 常见漏洞 (OWASP Top 10)
│   │   ├─ 注入: SQL/NoSQL/OS Command Injection
│   │   ├─ 失效访问控制: IDOR、水平/垂直越权
│   │   ├─ 敏感数据暴露: 加密缺失、明文传输
│   │   ├─ XSS: 存储型/反射型/DOM型
│   │   └─ CSRF: 跨站请求伪造
│   │
│   └─► 安全开发生命周期 (SSDLC)
│       ├─ SAST: 静态应用安全测试
│       ├─ DAST: 动态应用安全测试
│       ├─ SCA: 软件成分分析 (依赖漏洞)
│       └─ 渗透测试: 红队/蓝队
│
└─► 零信任架构 (Zero Trust)
    ├─ 核心原则: "从不信任，始终验证" (Never Trust, Always Verify)
    ├─ 假设 breach: 边界已失守、内部不可信
    ├─ 最小权限: 按需授权、动态评估
    ├─ 持续验证: 行为分析、风险评估
    └─ 代表: BeyondCorp (Google), Azure AD, Okta
```

## 二、零信任架构的形式化

```text
定义 (零信任访问决策):
  AccessDecision = f(Identity, Device, Context, Resource, Policy)

  Identity: 用户/服务身份 (已认证)
  Device: 设备状态 (合规性、健康度)
  Context: 上下文 (时间、地点、网络、行为异常)
  Resource: 请求的资源敏感性
  Policy: 动态策略 (ReBAC/ABAC)

  决策输出: {Allow, Deny, StepUpAuth, LimitAccess}

  与传统边界模型的区别:
    传统: InsideNetwork → Trust → AllowAll
    零信任: ∀Request → Verify → PolicyDecision
```

## 六、2025-2026行业数据更新

### 6.1 NIST后量子密码标准化进展

**NIST** (2024-2025): 后量子密码（PQC, Post-Quantum Cryptography）标准化进入实施阶段。2024年8月，NIST正式发布首批三项PQC标准——**ML-KEM**（密钥封装机制，原Kyber）、**ML-DSA**（数字签名，原Dilithium）和**SLH-DSA**（无状态哈希签名，原SPHINCS+）。这标志着全球密码基础设施向"抗量子计算"迁移的正式启动。

| 算法 | 类型 | 标准化状态 | 迁移紧迫度 | 性能影响 |
|------|------|-----------|-----------|---------|
| ML-KEM (FIPS 203) | KEM/密钥交换 | 已发布 | **高** | 比ECDH快或相当 |
| ML-DSA (FIPS 204) | 数字签名 | 已发布 | **高** | 签名较大(~3KB) |
| SLH-DSA (FIPS 205) | 哈希签名 | 已发布 | 中 | 签名极大(~8KB) |
| FN-DSA (原FALCON) | NTRU签名 | 草案阶段 | 中 | 较小签名(~0.7KB) |

**迁移时间线的关键假设**：NIST和CNSA（美国国家安全局）建议，持有需要长期保密数据（>10年）的系统应在2030年前完成后量子迁移。这一假设基于对"收获-现在-解密-以后"（Harvest Now, Decrypt Later, HNDL）威胁的评估——敌对国家可能正在截获加密流量，等待量子计算机成熟后解密。

**TLS 1.3 + 混合后量子**的部署已在Cloudflare、Google和部分金融机构中试点：在经典X25519密钥交换之外并行协商ML-KEM共享密钥，实现"加密即保险"的双层保护。但后量子算法的**签名大小**（ML-DSA签名约3KB，是传统ECDSA的10倍）对高并发API和TLS握手延迟构成挑战。

### 6.2 AI安全威胁：从应用层到模型层

**OWASP** (2025): LLM应用Top 10安全风险清单揭示了AI系统的新型攻击面：

| 风险排名 | 威胁类型 | 攻击向量 | 影响等级 |
|---------|---------|---------|---------|
| LLM01 | 提示注入（Prompt Injection） | 恶意输入操纵模型行为 | **严重** |
| LLM02 | 不安全输出处理 | 模型输出未过滤导致XSS/SSRF | 高 |
| LLM03 | 训练数据投毒 | 污染训练集植入后门 | 高 |
| LLM04 | 模型拒绝服务 | 资源耗尽型输入 | 中 |
| LLM05 | 供应链漏洞 | 预训练模型/框架缺陷 | 高 |
| LLM06 | 敏感信息泄露 | 训练数据记忆/泄漏 | **严重** |
| LLM07 | 不安全的插件设计 | 工具调用权限失控 | 高 |
| LLM08 | 过度代理权限 | 模型自主行为越权 | 高 |
| LLM09 | 模型窃取/提取 | 查询攻击重建模型 | 中 |
| LLM10 | 模型偏见/幻觉 | 输出不可靠导致决策错误 | 高 |

**对抗样本（Adversarial Examples）**的威胁正从学术概念转化为实际攻击：研究表明，通过精心构造的输入扰动（对人眼不可见），可以操纵视觉模型产生错误分类，或诱导LLM输出有害内容。更严峻的是**模型窃取攻击**：攻击者通过有限次数的API查询，可以重建目标模型的功能近似副本，绕过商业模型的访问控制和计费机制。

**NIST AI RMF** (2024-2025): NIST发布AI风险管理框架（AI RMF 1.0），将AI安全纳入企业风险管理的核心范畴。框架要求组织在AI系统的全生命周期中识别、评估和管理安全风险，涵盖数据治理、模型验证、部署监控和事件响应。

### 6.3 零信任架构的深化与扩展

### 6.4 批判性分析

后量子密码迁移面临**密码敏捷性（Cryptographic Agility）**的根本挑战：传统TLS/X.509基础设施的算法选择往往是硬编码的，替换为PQC算法需要协议栈、证书管理、硬件安全模块（HSM）和监控工具的全栈升级。更深层的问题是**性能-安全的权衡**：ML-DSA的签名大小是ECDSA的10倍，在带宽受限场景（IoT、移动网络、卫星通信）中，这意味着10倍的握手开销。组织需要基于数据敏感度进行差异化迁移——高敏感度系统优先迁移，低敏感度系统可延后。

AI安全威胁的独特性在于**攻击面的不可预测性**。传统应用安全的威胁模型假设攻击者利用已知漏洞（如SQL注入、缓冲区溢出），而AI系统的攻击向量（如提示注入、对抗样本）是随着模型能力涌现而持续演化的。这要求安全团队从"防御已知攻击"转向"构建抗攻击韧性"——一种更接近免疫系统而非防火墙的安全范式。

组织成熟度差异在安全领域表现为**安全左移（Shift Left）的深度**：高成熟度组织将SAST/DAST/SCA集成到IDE和CI/CD流水线中，缺陷在提交前即被发现；低成熟度组织仍依赖季度性的渗透测试。OWASP 2025调查显示，仅18%的组织实现了安全测试的全自动化集成——这一比例在过去三年中增长缓慢，表明安全工具链的集成复杂度是远比安全意识更硬的瓶颈。

## 七、批判性总结

零信任不是产品，而是**安全范式的根本转变**：从"信任但验证"到"永不信任，始终验证"。但零信任的实施面临**组织阻力**——它要求所有访问都经过认证和授权，这在传统企业中意味着巨大的流程重构。

JWT 的广泛滥用是 2026 年最大的应用安全隐患之一：开发者将 JWT 用作会话存储（放入大量声明），却忽视了**JWT 无法撤销**的本质。一旦泄露，攻击者在令牌过期前拥有完全权限。这印证了安全领域的永恒真理：**便利性 vs 安全性**的权衡中，工程师往往过度选择前者。

## 九、形式化推理链

### 8.1 公理 → 引理 → 定理 → 推论

**公理A1** (Saltzer & Schroeder, 1975 — 经济机制原则):
> 安全机制的设计应尽可能简单。每增加一个组件，就增加一个被攻击面。

**公理A2** (Shannon, 1949 — 完美保密):
> 若密钥长度 ≥ 消息长度且仅用一次，则系统达到信息论安全：H(M|C) = H(M)。

**引理L1** (BLP基本安全定理, Bell & LaPadula, 1976):
> 若系统初始状态安全，且所有状态转换规则均保持简单安全属性(Simple Security Property)和*-属性(*-Property)，则系统所有可达状态均安全。

形式化: ∀s₀ ∈ SecureState, ∀ rule ∈ Rules:
       secure(s₀) ∧ preserve(rule, secure) → ∀s ∈ Reachable(s₀): secure(s)

**引理L2** (Biba对偶性, Biba, 1977):
> 将BLP的"no read up, no write down"规则取逆（镜像），即可得到保护完整性的"no read down, no write up"。

**定理T1** (访问控制模型包含关系):
> RBAC ⊂ ABAC ⊂ ReBAC（表达能力层面）。
> 证明: RBAC的Role可表示为ABAC的单一属性；ABAC的策略可编码为ReBAC的关系约束。

**定理T2** (前向保密的组合安全性, Krawczyk, 2010):
> 在CDH假设下，(EC)DHE密钥交换 + HKDF密钥派生 → 会话密钥满足前向保密。
> 即: 长期私钥泄露 ⟹̸ 历史会话密钥可计算。

**推论C1**:
> TLS 1.3 强制 (EC)DHE，故在所有合规实现中，历史流量 confidentiality 在私钥泄露后仍保持。

**推论C2**:
> 零信任的"永不信任，始终验证"原则，本质上是将BLP的MAC策略从"位置属性"迁移到"多维度上下文属性"。

## 十二、深度批判性总结

安全模型的形式化谱系揭示了计算机安全领域一个深刻的认知演进：从**静态、二元的访问控制**走向**动态、连续的信任评估**。Bell-LaPadula (1973-1976) 和 Biba (1977) 作为状态机模型的双生子，分别用数学精确性定义了机密性与完整性，但它们的刚性也暴露无遗——BLP的"no read up, no write down"在商用环境中导致信息共享困难，Biba的"no read down, no write up"阻碍了高完整性进程读取外部输入。这两种模型的共同局限在于：它们假设安全等级是静态分配的，忽略了现代计算中上下文持续变化的本质。

Harrison-Ruzzo-Ullman (1976) 和 Take-Grant (1977) 将形式化从状态空间推向命令序列与权限流，但这些工作仍停留在"操作系统内核安全"的狭隘范畴。真正打破框架的是Diffie-Hellman (1976) 的公钥密码学思想——它证明了**安全通信不必依赖预先共享的秘密**，这一洞见直接催生了TLS、VPN和整个互联网商业生态。然而，密码学的数学保证与系统安全的工程现实之间存在永恒的鸿沟：Heartbleed、Shellshock、Log4j等灾难性漏洞表明，最精致的密码协议也可能因实现层面的缓冲区溢出或注入攻击而土崩瓦解。

零信任架构 (Kindervag, 2010; NIST SP 800-207, 2020) 代表了安全哲学从"防御边界"到"防御每个事务"的范式跃迁。其形式化内核——将访问决策函数从单一网络位置扩展到多维上下文向量——在理论上优雅，但在实践中面临严峻的**可用性税**和**可组合性挑战**。当每个微服务调用都需要策略评估时，延迟累积和策略冲突成为系统架构的瓶颈。2026年的前沿探索是将形式化验证（如TLA+对Zanzibar策略的模型检验）与机器学习驱动的异常检测相结合，但这又引入了新的可信计算基础问题：谁验证验证者？安全架构的终极悖论或许在于——**任何形式化系统都无法形式化地证明自身的完备性**，这正是Gödel不完备定理在安全工程中的幽灵回响。
